## 검증기가 잘못된 경로도 걸러내는지 확인

참고 좌표 제어형 환경으로 만든 대조 실험이며 개인 배정형 환경의 성능 비교용이 아니다.

| 입력 | 기대 | 실제 | 확인 |
|---|---|---|---|
| 샘플 선 전체 적층 | PASS | PASS | 충돌 0 |
| 로봇 3대를 같은 점으로 이동 | FAIL | FAIL | 충돌 이벤트 6 |
| 샘플 선의 절반만 적층 | FAIL | FAIL | 형상 검사 실패 |

저장 위치: `results/validation_controls/`.
추가 회귀 테스트에서는 개인 환경도 작업 목록을 절반만 주면 배정 자체는 완료되지만
run_validation은 형상 FAIL을 내는지 확인한다. 완료 플래그와 제출 합격을 구분하기 위한 검사다.

## 자동 테스트

최종 실행 결과: **14 passed, 1 warning, 3 subtests passed (7.12초)**.

개인 환경과 보조 대조 환경의 테스트 명령:

```powershell
python -B -m pytest test_assignment.py test_week1.py -q
```

검사 내용: SB3 환경 규격, seed 재현성, 잘못된 행동, 실패 시 경로 보존,
미완료 내보내기 차단, 종료 후 step 차단, 공식 충돌 경계값, 대기 로봇 충돌,
절점 사이의 충돌, 도달 불가능, CSV 구조, 입력 원본 보존, 실제 run_validation PASS/FAIL,
참고 환경의 과거 충돌 누적 처리.

참고 환경은 (3,5) 관측이라 SB3에서 1차원 관측을 권하는 경고가 1건 나온다.
개인 배정 환경은 1차원 관측을 사용한다. 경고는 테스트 실패나 Validator 경고가 아니다.
원본 `environment/test_gym_wrapper.py` 전체 테스트는 별도 pandas 의존성 때문에 이번 결과에 포함하지 않았다.

실행 라이브러리: Python 3.13.3, Gymnasium 1.3.0, Stable-Baselines3 2.9.0,
PyTorch 2.14.0(CPU 실행), NumPy 2.4.6, pytest 9.1.1.

Codex의 Windows 실행 영역에서 임시 폴더 ACL 때문에 발생하는 쓰기 문제를 피하기 위해,
검증 프로세스에만 임시 폴더의 상속 권한을 유지하는 보조 실행기를 사용했다.
제출 환경이나 원본 검증기에는 이 보조 코드를 넣지 않았고 검사 기준도 바꾸지 않았다.
일반 사용자 권한의 터미널에서는 README의 명령으로 실행하도록 작성했다.

## 팀에서 환경을 고를 때

1. 먼저 과제 범위를 맞춘다. 좌표 생성까지 하는 환경과 작업 배정만 하는 환경은 자유도가 다르다.
2. config, STL, 초기 위치, 작업 분할, 작업 후 복귀 의무, 종료 정의를 통일한다.
3. run_validation 통과율을 먼저 비교한다. FAIL의 짧은 makespan을 좋은 성과로 계산하지 않는다.
4. 통과 경로의 makespan, 도달/충돌 여유, 형상 점수, 계획 계산 시간을 비교한다.
5. 다음 주 학습 비교에서는 동일한 시간/샘플 예산과 여러 seed를 쓰고,
   학습에 쓰지 않은 형상에서도 평가한다. 평균·변동폭·실패율을 함께 기록한다.

현재 증명한 것은 **개인 환경이 실행되고, 그 출력이 팀의 run_validation과 연결된다**는 점이다.
6개 공개 형상 완료, PPO 성능, 새 STL 자동 경로 생성, 일반화, 최적 스케줄은 아직 증명하지 않았다.
