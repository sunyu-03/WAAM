첫 신규 모델은 학습 전 173.736655초에서 172.346940초로 개선되었다. 모든 최종 평가는 디스크의 ZIP을 다시 읽고 `trajectory.csv`를 내보낸 다음 공식 Validator 1.0.1을 실행했다. 마스크 제한 시험은 6개 작업에서 로봇 1개, 나머지 2개 작업에서 로봇 2개만 선택할 수 있었고, 금지 행동을 바꾸어 실행하는 우회는 없다. 짧은 제한 시험에서는 PPO가 Greedy보다 약간 느렸다.

동일 시드 반복은 **정책·가치 신경망의 모든 tensor와 최종 CSV 바이트가 동일**했다. 재개 후 가중치가 변했고 optimizer step은 **1,280 → 1,440**, 전체 학습 스텝은 **8,192 → 9,216**으로 이어졌다. 재개는 정책·optimizer·학습 스텝·전역 RNG를 복구하고 새 rollout에서 환경을 reset한다. 중간 rollout의 상태까지 비트 단위로 이어가는 방식은 아니다.

계약 불일치(작업 목록/여유 거리), ZIP/RNG 파일 변조, 기존 13개 입력 모델을 로드 전에 거부한다. 기존 성공 ZIP의 SHA256 두 값은 보존을 확인했다. 회귀 검증 **13개 PASS**: 기존 파이프라인 7개 + 새 PPO 계약·마스크·디코더·파일 검증 6개. 모든 학습 실행의 소스 변경 감지 결과는 false다.

재현 근거는 `evidence/ppo_20261009_001/` 아래에 있다. sample8, repeat, resume, masked, eval_only 각각의 `run.json`, `tasks.json`, 체크포인트/manifest/RNG, 학습 CSV, 공식 보고서와 trajectory를 보관했다. `verification.json`은 tensor/optimizer/CSV/기존 체크포인트 비교 결과다.

## 입력과 행동의 정확한 의미

새 계약 ID는 `waam-serial-masked-v1`이다. 관측은 작업 수와 무관한 float32 **16개**: 진행률, 시작 XYZ, 끝 XYZ, 길이, 로봇별 왕복 시간 3개, 로봇별 mask 3개, 이동/적층 속도 2개다. 좌표·길이는 시나리오 최대 절대 좌표, 시간은 전체 작업의 최대 왕복 시간, 속도는 두 속도의 최댓값으로 나눈다. 작업 수가 1/4/8개인 환경에서 동일한 입력 크기를 검증했다.

행동은 **Discrete(3)**, 0/1/2가 로봇 1/2/3이다. 한 행동이 현재 작업의 `home → start → deposit → home` 전체 이동을 배정한다. 준비 단계에서 공식 궤적·도달·충돌 검사로 각 작업의 가능한 행동을 확인한다. 각 trip은 홈에서 시작하고 끝나며 다른 로봇은 대기한다. 실행은 순차이고 학습과 CSV 디코더가 동일하다. 전체 조립 출력에 대해 형상·레이어와 시간 기준까지 다시 공식 검증한다. step 검사만으로 형상 PASS를 주장하지 않는다.

보상은 `-선택 trip 시간 / 최대 trip 시간`이다. 순차 합산 비용이 작업별로 독립이므로 gamma=0이다. 이 제한된 문제에서는 작업마다 최소 비용 로봇을 선택하는 Greedy가 해석적으로 최적이다. 따라서 PPO의 목적은 학습 연결과 안전한 배정 검증이며, Greedy를 초월하는 경로 최적화 성과로 제시하지 않는다. 예전 레이어 유지 Greedy의 같은 sample 30.469707초와는 홈 복귀 횟수가 달라 직접 성능 비교하면 안 된다.

MaskablePPO 2.9.0 / stable-baselines3 2.9.0 / torch 2.14.1+cpu / gymnasium 1.4.0, CPU 1 thread, 결정적 알고리즘, seed 42를 사용했다. MLP [64,64], lr=3e-4, rollout=128, batch=64, epochs=10, entropy=0.01, GAE=1.0이다. 학습 스텝은 128 단위로 올림 처리한다. 2,048스텝마다 학습 업데이트를 완료한 체크포인트와 최종 모델을 저장한다. 각 ZIP 옆의 JSON 두 파일도 함께 유지해야 재개할 수 있다.

`requirements-ppo.txt`는 추가 학습 의존성, `ppo_runtime.lock`은 관측된 전체 환경 버전이다. 라이브러리는 통합 폴더의 `.deps/`에만 추가했다. 공식 Validator 코드는 저장소의 `TEAM_PROJECT/week1/environment`를 사용한다. 새로운 컴퓨터에서 깨끗한 환경 재설치는 이번에 시험하지 않았다.

## VS Code에서 코드 보기 및 실행

현재 열어 둔 integration 폴더에서 **train.py**를 다시 보면 학습 코드가 보인다. 환경 구현은 **algorithm → environment → ppo_env.py**다.

integration 폴더용 `.vscode/launch.json`을 추가했다. Restricted Mode라면 본인이 만든 통합 폴더를 신뢰하도록 설정하고, 실행 목록에서 **WAAM PPO: 작은 모델 학습 + 공식 검증**을 선택해 F5를 누른다. 기존 결과와 겹치지 않는 새 폴더 이름을 입력한다. 터미널에서 같은 인자로 실행하는 것은 확인했으며 F5의 UI 동작 자체는 직접 시험하지 않았다.

VS Code PowerShell 터미널 실행:

```powershell
Set-Location 'C:\Users\User\Desktop\AInAlgorithm\waam_generalization\integration'
$waamPython = 'C:\Users\User\Desktop\WAAM_Validator-main\.venv\Scripts\python.exe'
& $waamPython train.py --job ../TEAM_PROJECT/week1/environment/examples/sample_job --demo-segments 8 --timesteps 8192 --out runs/my_ppo_001
```

학습 재개(결과 폴더는 새 이름, `--seed`는 원래 체크포인트와 동일해야 한다):

```powershell
& $waamPython train.py --job ../TEAM_PROJECT/week1/environment/examples/sample_job --demo-segments 8 --timesteps 1024 --resume evidence/ppo_20261009_001/sample8/ppo_serial.zip --out runs/my_ppo_resume_001
```

저장한 모델만 검증하려면 같은 입력 인자에 `--resume ... --eval-only`를 지정한다. 최종 체크포인트는 결과 폴더의 `ppo_serial.zip`, 최종 궤적은 `ppo/job/trajectory.csv`, 공식 보고서는 `ppo/validation/`, 학습 수치는 `logs/progress.csv`다.

새 환경 설치가 필요한 경우 기존 성공 환경에 설치하지 않고, 통합 폴더의 `.deps` 또는 별도 가상환경을 사용한다. 기존 `.deps`를 다시 맞출 때는 다음 명령을 사용할 수 있다(이번 실행에서는 라이브러리를 나누어 설치했다).

```powershell
$env:TEMP = (Resolve-Path tmp).Path
$env:TMP = $env:TEMP
& $waamPython -m pip install --no-cache-dir --upgrade --target .deps -r ppo_runtime.lock
```

public Model 01의 저장 작업을 이용한 학습 시작 예시(이번에는 이 6개 공개 모델 PPO 학습은 실행하지 않았다):

```powershell
& $waamPython train.py --job C:/Users/User/Desktop/WAAM_Validator-main/tests/01 --tasks-json evidence/20261009/01/tasks.json --timesteps 16384 --out runs/my_model01_ppo_001
```

`--tasks-json`을 생략하면 공식 STL/config로 Task Generator를 실행한다. 표본 일부만 학습해 전체 모델 PASS를 주장하지 않도록 최종 평가는 입력된 모든 작업으로 실행한다.

최종 코드에서 보관된 체크포인트를 `--eval-only`로 읽어 다시 세 방법 모두 PASS를 확인했다(`evidence/ppo_20261009_001/eval_final/`). 재개 시 seed 7을 잘못 지정하면 모델을 로드하거나 결과 폴더를 만들기 전에 거부하는 CLI 시험도 통과했다.

## 남은 개발

레이어 내 위치 유지, 작업 순서 선택, 여러 로봇 동시 이동을 PPO 행동에 연결하는 일이 남아 있다. 현재 v1의 mask는 홈 왕복 trip에 대한 것이므로 레이어 경로에 그대로 재사용하면 안 된다. 다른 디코더에는 새 계약과 학습이 필요하다. 현재는 단일 job을 반복하며 학습하고, 다른 STL/config로 이어 학습하는 재개는 거부한다. 여러 모델을 대상으로 하는 혼합 학습과 별도 평가 입력을 지원하려면 데이터셋 계약을 확장해야 한다.

6개 모델의 기존 Greedy PASS와 최선 기록은 보존했다. 새 PPO로 6개 전체 모델의 더 좋은 해를 확보하거나 전역 최적성을 증명한 것은 아니다. GitHub 원격에는 아직 제출하지 않았으며 별도 통합 브랜치에 코드와 연결 검증 근거를 기록한다.
